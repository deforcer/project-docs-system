# Project Docs System

Скилл помогает создать и вести систему проектной документации: контекст,
изменения, решения, проверки, процедуры и память между сессиями.
Подходит для разработки, QA, исследований и организационных проектов.

Версия: **0.1.0**. Исходники — `skills/project-docs-system/`.

## Что можно попросить

- «Примени $project-docs-system к новому проекту. Я тестировщик, первая задача — организовать регрессию».
- «Адаптируй нашу существующую документацию с помощью $project-docs-system. Сохрани структуру и договорённости».
- «Используй $project-docs-system: обнови связанные документы после этого изменения и оставь контекст для продолжения».

Скилл сначала изучает проект, затем создаёт необходимые документы с учётом
его масштаба. Для маленькой задачи достаточно короткой заметки с проверкой.
Для значимого изменения связываются требования, решения, сценарии и результаты.
Неизвестные факты остаются открытыми вопросами.

## Быстрая установка через агента

Скопируйте в Codex, Claude Code или другой клиент с поддержкой Agent Skills:

```text
Установи project-docs-system из https://github.com/deforcer/project-docs-system
для текущего пользователя.

Определи текущий клиент, ОС и поддерживаемый каталог личных скиллов с учётом
его настроек. В Claude Code добавь marketplace deforcer/project-docs-system
и установи project-docs-system@project-docs-system в user scope.
В Codex и других клиентах установи целиком skills/project-docs-system
через доступный установщик скиллов или в поддерживаемый каталог клиента.

Не привязывай установку к каталогу проектов или текущему рабочему каталогу.
Для Git-копии при необходимости выбери постоянное служебное место пользователя.
При существующей установке сначала проверь её источник и пользовательские правки;
не перезаписывай их и не создавай дубли. Сохрани сведения об источнике обновлений.
Проверь доступность SKILL.md, references, assets и регистрацию скилла в клиенте.
Если нужна новая сессия или ручной шаг, сообщи об этом. Не создавай расписаний
обновления без отдельного запроса.
```

Расположение проектов пользователя не имеет значения. Клиент выбирает место
установки; клон в `Projects` и символические ссылки не требуются. Скилл работает
в клиентах с поддержкой локальных Agent Skills. В среде без такой поддержки
можно явно передать ассистенту SKILL.md и остальные файлы пакета.

## Установка вручную

### Claude Code: плагин из marketplace

В терминале с установленным Claude Code:

```sh
claude plugin marketplace add deforcer/project-docs-system
claude plugin install project-docs-system@project-docs-system --scope user
```

Claude Code сам хранит плагин в своём каталоге. После установки откройте новую
сессию. Команда скилла: `/project-docs-system:project-docs-system`.

Для проверки установки используйте `claude plugin list`. Если скилл раньше
устанавливался отдельной папкой, проверьте источник обеих установок и сохраните
свои правки перед выбором одной версии.

### Codex

Попросите встроенный установщик скиллов установить пакет по ссылке:

```text
Установи с помощью $skill-installer скилл из
https://github.com/deforcer/project-docs-system/tree/main/skills/project-docs-system
```

Если установщик недоступен, используйте копирование папки, описанное ниже.
После установки откройте новую сессию и вызовите `$project-docs-system`.

### Копирование папки: Codex, Claude Code и другие клиенты

Скачайте ZIP репозитория через GitHub или клонируйте его в любое удобное место:

```sh
git clone https://github.com/deforcer/project-docs-system.git
```

Скопируйте **всю папку** `skills/project-docs-system/` в каталог скиллов клиента.
В установленной папке должны остаться `SKILL.md`, `agents/`, `references/`
и `assets/`. Одного файла SKILL.md недостаточно.

| Клиент | Для пользователя | Для одного проекта |
| --- | --- | --- |
| Codex | `~/.agents/skills/project-docs-system/` | `.agents/skills/project-docs-system/` в целевом проекте |
| Claude Code, без плагина | `~/.claude/skills/project-docs-system/` | `.claude/skills/project-docs-system/` в целевом проекте |
| Другие клиенты Agent Skills | Поддерживаемый клиентом каталог личных скиллов | Поддерживаемый клиентом каталог проектных скиллов |

Здесь `~` — домашний каталог текущего пользователя; в Windows PowerShell ему
соответствует `$HOME`. Пути в таблице — стандартные каталоги клиентов,
а не обязательная структура хранения ваших проектов. Учитывайте настройки
конкретного клиента. При существующей папке сначала сравните содержимое
и сохраните пользовательские изменения; не копируйте поверх неё вслепую.

Копирование работает без символических ссылок и Windows Junction. При таком
способе исходный клон можно хранить в любом месте или удалить после установки.
Проверьте, что скилл виден в новой сессии: Codex — `$project-docs-system`,
Claude Code при установке папкой — `/project-docs-system`. Наличие файлов
само по себе не подтверждает загрузку скилла в клиент.

Официальные инструкции: [Codex](https://developers.openai.com/codex/skills/),
[скиллы Claude Code](https://code.claude.com/docs/en/skills),
[marketplace Claude Code](https://code.claude.com/docs/en/plugin-marketplaces).

## Первый запуск

Откройте **целевой проект**, затем укажите роль, первую задачу и место хранения:

```text
Используй $project-docs-system.
Проект: внутренний каталог услуг.
Моя роль: аналитик.
Материалы уже лежат в docs; сохраняй действующие названия.
Первая задача: описать обработку заявки и способ её проверки.
```

Результат — понятная навигация, адаптированные правила работы, нужные шаблоны
и документы первой задачи. Файлы задач создаются в целевом проекте.
Если вы хотите только план, прямо укажите это в запросе.

## Обновление

Для плагина Claude Code обновите marketplace и установленный плагин:

```sh
claude plugin marketplace update project-docs-system
claude plugin update project-docs-system@project-docs-system --scope user
```

Затем откройте новую сессию. Автообновление можно включить отдельно через
настройки marketplace в Claude Code.

Для установки папкой попросите агента обновить скилл из того же репозитория,
сравнить изменения и сохранить ваши правки. При ручном обновлении скачайте
новую версию, сохраните старую установку и замените пакет целиком после сравнения.
Если вы храните Git-копию, обновляйте её через `git pull --ff-only` только
при отсутствии локальных изменений, затем обновите установленную копию.
Для установки через ссылку достаточно обновить её исходную Git-копию.

Версия методики указана в metadata.version файла SKILL.md, версия плагина —
в `.claude-plugin/plugin.json`. Документы целевых проектов автоматически
не меняются: их адаптация требует отдельного запроса.

## Разработка и проверка

Проверки выполняются локально. Конфигурация CI/CD в репозитории не предусмотрена.

```bash
python3 scripts/validate.py
```

Валидатор проверяет комплектность, локальные ссылки, замкнутость пакета и
отсутствие характерных данных исходного workspace. Он не оценивает качество
решений ассистента и не проверяет внешние URL или Markdown-якоря.
[Сценарии приёмки](tests/scenarios.md) проверяются отдельно.
[Результаты первой версии](tests/results-v0.1.0.md) указывают фактический объём проверки.

Скилл содержит самостоятельную методологию проектной документации, шаблоны
и инструкции по их адаптации. Дальнейшие изменения ведутся в этом репозитории.
