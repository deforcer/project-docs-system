# Project Docs System

Скилл помогает создать и вести систему проектной документации: контекст,
изменения, решения, проверки, процедуры и память между сессиями.
Подходит для разработки, QA, исследований и организационных проектов.

Версия: **0.1.0**. Исходники — `skills/project-docs-system/`.

## Что можно попросить

- «Примени $project-docs-system к новому проекту. Я тестировщик, первая задача — организовать регрессию».
- «Адаптируй нашу существующую документацию с помощью $project-docs-system. Сохрани структуру и договорённости».
- «Используй $project-docs-system: обнови связанные документы после этого изменения и оставь контекст для продолжения».

Скилл сначала изучает проект, затем создаёт необходимые документы с учётом
его масштаба. Для маленькой задачи достаточно короткой заметки с проверкой.
Для значимого изменения связываются требования, решения, сценарии и результаты.
Неизвестные факты остаются открытыми вопросами.

## Установка

Нужны Git и ассистент с поддержкой локальных Agent Skills. Для работы скилла
не нужны Python, MCP или доступ к Jira. Python 3.9+ нужен только разработчику
скилла для локального валидатора.

### macOS / Linux / WSL

В обычном терминале:

```bash
mkdir -p ~/Projects ~/.agents/skills
cd ~/Projects
git clone https://github.com/deforcer/project-docs-system.git
ln -s ~/Projects/project-docs-system/skills/project-docs-system ~/.agents/skills/project-docs-system
```

Перед созданием ссылки убедитесь, что путь `~/.agents/skills/project-docs-system`
свободен. Если установка уже есть, сначала выясните, куда она указывает;
не создавайте вложенную ссылку и не заменяйте чужие файлы.

### Windows PowerShell

```powershell
New-Item -ItemType Directory -Force "$HOME\Projects"
New-Item -ItemType Directory -Force "$HOME\.agents\skills"
Set-Location "$HOME\Projects"
git clone https://github.com/deforcer/project-docs-system.git
New-Item -ItemType Junction -Path "$HOME\.agents\skills\project-docs-system" -Target "$HOME\Projects\project-docs-system\skills\project-docs-system"
```

Для ручной
установки скопируйте целиком `skills/project-docs-system/` в каталог скиллов
вашего ассистента. В копии нужны и `references/`, и `assets/`.

Codex поддерживает пользовательские скиллы в `~/.agents/skills`, включая
символические ссылки. Подробнее: [документация Codex](https://developers.openai.com/codex/skills/).
Если скилл не виден, откройте новую сессию и проверьте, доступен ли его SKILL.md
по установленному пути. Установка папки не подтверждает её загрузку в уже
открытую сессию. В другой среде выберите её поддерживаемый каталог скиллов
либо явно передайте ассистенту SKILL.md с доступом к остальным файлам пакета.

## Первый запуск

Откройте **целевой проект**, затем укажите роль, первую задачу и место хранения:

```text
Используй $project-docs-system.
Проект: внутренний каталог услуг.
Моя роль: аналитик.
Материалы уже лежат в docs; сохраняй действующие названия.
Первая задача: описать обработку заявки и способ её проверки.
```

Результат — понятная навигация, адаптированные правила работы, нужные шаблоны
и документы первой задачи. Файлы задач создаются в целевом проекте.
Если вы хотите только план, прямо укажите это в запросе.

## Обновление

В клоне с исходниками:

```bash
git pull --ff-only
python3 scripts/validate.py
```

При установке через symlink/Junction обновляется доступная скиллу папка.
Если проверка не прошла, разберите ошибку перед использованием новой версии.
При ручном копировании сначала сохраните старую установку отдельно и сравните
свои правки, затем замените пакет целиком. Документы целевых проектов
автоматически не меняются: их адаптация требует отдельного запроса.
Версию пакета смотрите в metadata.version файла SKILL.md; фиксированную версию
можно установить из Git tag `v0.1.0` в отдельном клоне.

## Разработка и проверка

Проверки выполняются локально. Конфигурация CI/CD в репозитории не предусмотрена.

```bash
python3 scripts/validate.py
```

Валидатор проверяет комплектность, локальные ссылки, замкнутость пакета и
отсутствие характерных данных исходного workspace. Он не оценивает качество
решений ассистента и не проверяет внешние URL или Markdown-якоря.
[Сценарии приёмки](tests/scenarios.md) проверяются отдельно.
[Результаты первой версии](tests/results-v0.1.0.md) указывают фактический объём проверки.

Скилл содержит самостоятельную методологию проектной документации, шаблоны
и инструкции по их адаптации. Дальнейшие изменения ведутся в этом репозитории.
