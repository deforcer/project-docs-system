# Сопровождение изменения

Прочитай описание задачи, её требования, решения и результаты. Выясни, что
изменилось фактически и какое состояние только предложено. Проверь актуальный
источник там, где вывод зависит от текущего состояния; при отсутствии доступа
укажи ограничение и дату доступных сведений.

## Что обновлять вместе

| Изменение | Связанные материалы |
| --- | --- |
| Требования или объём | Feature/spec, затронутые сценарии, decision при существенном выборе |
| Процедура команды | Process/procedure, критерии, инструкции роли |
| Критерии входа или завершения | DoR/DoD, применимые шаблоны и проверки |
| Методика | Основной документ, объяснение результата, примеры, проверки |
| Внешний интерфейс | Описание интеграции, ограничения, примеры и проверки |
| Система документации | Навигация, шаблоны, инструкции ассистента, init |
| Замена документа | Статус старого, ссылка на замену, актуальная навигация |

Таблица помогает найти затронутые материалы; не создавай отсутствующие документы
только ради её заполнения. Предпочитай ссылки повторению нормативного текста.

## Проверки и фактический результат

Свяжи критерий с проверкой; для выполненной проверки укажи дату, версию/условия,
результат и доказательство. Возможны «пройдено», «не пройдено», «не проверено»,
«не применимо» с причиной. При изменении требований старый результат остаётся
историческим; он не подтверждает новую версию автоматически.
Для повторяемой аналитики сохраняй методику, входы и условия сравнимости.

## Передача

В work-log запиши существенное изменение, проверку и ссылки. В resume-контексте
оставь текущую задачу, сделанное, разрешения в их исходных границах, неизвестное
и следующий шаг. Важные решения должны быть в общих документах проекта.
Статус Done ставь после выполнения критериев согласованного объёма.
Если остались препятствия, объясни их и укажи доступный следующий шаг.
